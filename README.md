# Jamming-resilient INS-aided deep tracking of NavIC signals

MATLAB and Python code that generates all results of:

> J. Sanwale, M. Kothari, and H. Hablani, *An Electronic Warfare Framework for Jamming-Resilient INS-Aided Deep Tracking of NavIC Signals* (IEEE TAES, revision R1).

The manuscript itself is not part of this repository. The scripts write their tables and figures to a local folder `paper/R1`, which is created on first use and ignored by git.

- **Simulator.** Eight-element (7+1) controlled reception pattern antenna (CRPA) IF signal generation for NavIC L5 SPS on a high-performance aircraft: a nonlinear F-16 six-degree-of-freedom model with an autopilot, a navigation-grade IMU model, the seven-satellite NavIC constellation, and broadband, chirp, pulsed (DME) and compound jammers.
- **Array processing.** Single element, power inversion (PI), and INS-steered per-satellite MVDR beams with the body-rate block schedule and pulse blanking.
- **Receiver.** The INS-aided ultratight (UT) NavIC receiver, with classical scalar tracking (CT) for the handover, and the array aiding of the manuscript (beam-phase feed-forward, array-informed C/N0 cap, blanking-aware loop C/N0). The receiver also supports GPS L1 C/A, which the anti-jamming study does not use.

## Requirements

- **MATLAB:** R2023a or later, with the Signal Processing, Communications, and Curve Fitting Toolboxes.
- **Python 3** with NumPy, SciPy and Matplotlib, for the jammer localization and the array-level figures.
- **Tested setup:** MATLAB R2025b on Windows 10.
- **Disk space and time:** the navigation-level campaign keeps about 670 GB of raw eight-element IF and takes about 9.5 days with two MATLAB sessions (see *Reproducing the results*).

No other software or downloads are needed. The broadcast ephemerides are included in the `Simulator` folder.

## Quick start

From the MATLAB command window, in the repository folder:

```matlab
init
```

`init` opens the mode menu; each mode is one step of *Reproducing the results* and prompts for its options. Press Enter to accept the default shown in brackets.

## What the code contains

- **`Simulator/generateIFdataArray.m`, `signalGeneratingArray.m`, `arrayGeometry.m`, `jammerWaveform.m`.** Eight-element NavIC L5 IF generation with broadband, chirp, pulsed (DME) and compound jammers, mutual coupling, and the seven-satellite constellation (four from broadcast ephemerides, three artificial satellites in the vacant slots, `navicArtificialEph.m`).
- **`ArrayProcessor/arrayProcess.m`.** Single element, power inversion (PI), and INS-steered per-satellite MVDR beams with the body-rate block schedule, pulse blanking, and the array log: beam phase, SINR gain and blanked fraction every 1 ms. Option `steerAtt 'gnss'` steers without INS attitude (the no-INS ablation).
- **Receiver aiding** (`Receiver/acqtckpos/trackingUT_POS.m`, option `track.utArrayAid`):
  - `a`: carrier feed-forward of the beam phase;
  - `d`: array-informed C/N0 cap with an envelope-tracked reference;
  - `n`: blanking-aware loop C/N0.
- **`aj/`.** Campaign driver, scenarios S1–S3, metrics, the two ablations (no-INS steering; INS steering with a fixed block), jammer localization (`jammer_localization.py`), and the mode menu (`ajMenu.m`).
- **`aj/paper/`.** Scripts that turn the campaign results into the manuscript's tables and figures.

## Data folders

No IF data are stored in the repository: every IF file is generated by the code. The generated data go to folders outside the repository under a base folder `<base>` (`aj/ajPath.m`). `<base>` is the environment variable `AJ_DATA_ROOT` or, if it is not set, the parent folder of the repository.

| Folder | Content |
|---|---|
| `<base>\data\FighterProfiles` | trajectories and IMU files (generated on first use) |
| `<base>\step4\clean_single\out` | jammer-free reference run; its decoded ephemeris warm-starts every campaign run |
| `<base>\campaign\rawIF\<id>` | raw eight-element IF of each item (9.6 GB per item; deterministic, seed 100 + realization) |
| `<base>\campaign\results` | per-item metrics: `<id>.mat`, and `noins_<id>.mat` and `insfix_<id>.mat` for the two ablations |
| `<base>\campaign\loc` | jammer-localization inputs and results |

The full campaign keeps about 670 GB of raw IF. That is needed only for the two ablations and the localization; without it, those steps regenerate the IF of an item.

## Reproducing the results

**Mode selection.** `init` opens the mode menu (`aj/ajMenu.m`), which runs each step below by number and asks for its options (worker, number of workers, seeds, item ids). Option 8 runs steps 2–4 for a single seed. The menu also runs without prompts from an `AJ` struct, set before `init.m` or passed to `ajMenu`:

```matlab
addpath(fullfile(pwd, 'aj')); ajMenu(struct('mode', 2, 'worker', 1, 'nWorkers', 2, 'seeds', 1:10))
```

| `AJ` field | Meaning |
|---|---|
| `mode` | step 1–7 below, or 8 (steps 2–4 for one seed) |
| `worker`, `nWorkers` | worker index and number of parallel MATLAB sessions; default 1 and 1 |
| `seeds` | realizations; default `1:10` |
| `ids` | items for jammer localization (step 6) |

The Python steps use `python` on the system path, or the interpreter named by the environment variable `AJ_PYTHON`.

The steps can also be run directly from MATLAB in the repository folder (`<repo>`), or with `matlab -batch`, in this order:

1. **Jammer-free reference** (also generates the trajectories and runs the first jammed checks):
   ```matlab
   run(fullfile(pwd, 'aj', 'run_step4_tests.m'))
   ```
2. **Navigation-level campaign** (Tables III–IV, Fig. 9). 70 items: scenarios S1–S3 × profiles × 10 realizations. Each item takes 2–4.5 h; with two MATLAB sessions, about 9.5 days. The runs are resumable, and the two workers run in parallel:
   ```matlab
   addpath(fullfile(pwd, 'aj')); run_campaign(1, 2, 1:10)   % worker 1 of 2
   addpath(fullfile(pwd, 'aj')); run_campaign(2, 2, 1:10)   % worker 2 of 2
   ```
3. **No-INS ablation** (Section VII-D). About 23 h with two workers, on the stored raw IF:
   ```matlab
   addpath(fullfile(pwd, 'aj')); run_noins_campaign(1, 2, 1:10)
   addpath(fullfile(pwd, 'aj')); run_noins_campaign(2, 2, 1:10)
   ```
4. **INS steering with a fixed 10-ms block** (Section VII-D). Separates the INS steering from the body-rate schedule, on the stored raw IF:
   ```matlab
   addpath(fullfile(pwd, 'aj')); run_insfix_campaign(1, 2, 1:10)
   addpath(fullfile(pwd, 'aj')); run_insfix_campaign(2, 2, 1:10)
   ```
5. **Tables and Fig. 9.** These write `paper/R1/paper_results.txt` and `fig_campaign.pdf`, and print the Section VII-D statistics:
   ```matlab
   addpath(fullfile(pwd, 'aj', 'paper')); paper_results; noins_summary; insfix_summary;
   ```
6. **Jammer localization** (Section VI-C, Fig. 8):
   ```matlab
   addpath(fullfile(pwd, 'aj')); export_localization({'S1_baseline_cruise_s01', 'S1_break_gonset_s01'})
   ```
   then, with Python 3 (NumPy, SciPy, Matplotlib):
   ```bash
   python aj/jammer_localization.py S1_baseline_cruise_s01 S1_break_gonset_s01
   ```
7. **Array-level figures** (Figs. 3, 6, 7, 8). They write to `paper/R1`, or to `FIG_OUT` if set:
   ```bash
   python aj/paper/figures/crpa8_element_patterns.py
   ```
   ```bash
   python aj/paper/figures/crpa8_pattern.py
   ```
   ```bash
   python aj/paper/figures/crpa8_roll_nulling.py
   ```
   ```bash
   python aj/paper/figures/fig_jammer_loc.py
   ```
   `fig_jammer_loc.py` writes the two-column `fig_jammer_loc.pdf`; with the environment variable `FIG_LAYOUT=column` it writes the one-column `fig_jammer_loc_col.pdf` used in R1. Menu steps 6 and 7 write both.

The marker jitter in Fig. 9 is random (seeded), so a regenerated figure differs from the manuscript's only in the horizontal marker positions.

## Repository layout

| Path | Content |
|---|---|
| `init.m` | entry point: opens the mode menu (`aj/ajMenu.m`) |
| `Simulator/` | eight-element NavIC IF generation, jammers, array geometry, F-16 model and autopilot (`F16Aircraft/`), IMU model, antenna patterns, broadcast ephemerides (RINEX) |
| `ArrayProcessor/` | CRPA array processing: PI, INS-steered per-satellite MVDR, body-rate schedule, blanking |
| `Receiver/` | receiver entry (`init.m`, called by the campaign) and parameters |
| `Receiver/acqtckpos/` | acquisition, CT and UT tracking with array aiding, positioning, navigation-message decoding, truth comparison |
| `Receiver/geo/` | coordinate, Earth-rotation, and ionosphere functions |
| `Receiver/common/` | functions shared with the simulator (troposphere, trajectory spline, profile list) |
| `Receiver/report/` | per-run result tables |
| `aj/` | campaign, scenarios S1–S3, metrics, the two ablations, jammer localization, mode menu |
| `aj/paper/` | tables (`paper_results.m`, `noins_summary.m`, `insfix_summary.m`) and figure scripts (`figures/`) |
